# A maps section in Sasonica (6 Nov 2026)

David, 6 Nov 2026: "I'd like to discuss adding a maps section to the
sasonica". Asked what it is for, he picked all four offered (agents show
places, where things are, location history, navigation by voice) and
added: "I'd also liked it to overlay other information like speed cameras
and mobile phone detection, cameras and things like that". Status:
**steps 1 and 2 built (9 Nov 2026), step 3's OSM cameras 10 Nov; the rest proposed.**

## The shape: one map, many layers

A single Map page in the app. The server says which layers exist and
serves each as GeoJSON. The app draws what it is sent and knows nothing
about where the data comes from (docs/decisions/2026-09-21-app-stays-generic.md).

- `GET /map/layers` → `[{id, name, kind: points|lines|track|route, icon?,
  colour?, default_on, refresh_s?, private?}]`
- `GET /map/layers/<id>?bbox=w,s,e,n` → a GeoJSON FeatureCollection, each
  feature with `title`, `detail?` and `link?` (a thread, a device, a URL).
- A layer source is a small server-side plugin (a Python entry point, as
  the personal-use add-ons are), so a region's camera feed or a house's
  floor plan lives in an add-on or on the host and never in this repo
  (no host config in agent-media).

**Drawing.** MapLibre GL JS (BSD-3) in the WebView, with vector tiles.
For tiles: start with a hosted OpenStreetMap-based provider (OpenFreeMap
needs no key), with a self-hosted Protomaps PMTiles file of Victoria on
red5 as the fallback, served by the server over public HTTPS (not the
tailnet). On the Pine Note: a greyscale line-art style, no fills or
animation.

## The layers

1. **Agent places.** A reply carries `[[map: …]]` (pins, a route, a box),
   as replies carry `[[visual: …]]` now. The thread shows a small map
   inline. Tapping it opens the Map page with that reply's layer on. Each
   thread's places are kept as a layer (`thread:<id>`) until the thread
   goes.
2. **Where things are.** Devices, rooms and speakers placed once by hand
   (drag a pin, or "the kitchen speaker is here"), plus the phone's live
   dot from §6.21b. A floor plan comes later, as an image overlay on the
   house.
3. **Location history.** The biggest privacy change in this proposal,
   see below.
4. **Overlays from open data.**
   - Fixed speed and red-light cameras: OSM `highway=speed_camera`, plus
     the Victorian government's published list if there is one under an
     open licence (to check: what is published, how often it is updated,
     and the licence).
   - Mobile phone detection cameras: in Victoria these move. To check what
     is published (whether it names sites, a schedule, or nothing). If
     nothing, the layer shows known sites only and says so. It never
     guesses.
   - Surveillance cameras: OSM `man_made=surveillance` (Overpass query,
     cached daily per region).
   - Each overlay shows how old its data is. A camera layer never claims
     to be complete.
   - Legality: camera alerts are legal in Victoria (Waze and others do
     it). To check before any public build in other places; some
     countries ban them (e.g. France, Switzerland, parts of Germany).
     Public builds get a per-region switch, set on the server.
5. **Navigation by voice.** Last, as it is the largest piece:
   - A routing engine on red5: Valhalla (MIT) or GraphHopper (Apache-2.0)
     on the Victoria extract. OSRM is lighter but car-first.
   - The phone sends its position while a route is on. The server works
     out the next instruction and speaks it through the usual speech
     path, ducked under music and held during a call (call_guard).
   - Camera alerts are spoken on the route ("speed camera in 300
     metres") from layer 4.
   - Audio-first: designed to be used without looking, as in
     `2026-11-05-audio-first-messenger.md`.

## Location history and privacy

Today the phone's shared location is kept **in memory only**, never
written to disk, newest per phone (§6.21b). That was chosen on purpose
(David, 20 Oct 2026: "location data … as an optional extra with the
default being off"). History has to change it, so:

- It is a separate switch, off by default: "Keep where I've been".
- It is stored on the user's own server only, in its own file
  (`location.db`), never synced to the long-term memory store or sent to
  any model provider. An agent reads it through a tool, and only the
  answer goes into the chat ("you were at Southland on Tuesday, about
  2 pm").
- Points are thinned on the phone: a point when it has moved more than
  about 50 m, or every few minutes while still. Stays are grouped into
  visits (place, from, to).
- Kept for 90 days by default (30 days, one year or forever in Settings), with "forget today"
  and "forget everything" in Settings.
- Battery: the Android fused provider at balanced power, and only while
  moving. To measure on the p8a before turning it on for anyone.
- Later, with it: reminders tied to a place ("remind me when I'm at
  Bunnings"), and the music bed and briefing knowing whether you are
  home, out or driving.

## Order to build

1. The Map page, `/map/layers`, tiles, and the phone's live dot. **Built 6–9 Nov
   2026** (server §6.50, `map_layers.py`; app `routes/maps.tsx`).
2. Agent places (`[[map: …]]`), inline in threads. **Built 9 Nov 2026**: `[[map:]]`
   and `[[route:]]` with coordinates from `media place find` (no geocoding at
   display time), a card under the reply, the chat's places as a Map layer.
3. Camera overlays (OSM first, then Victorian government data once checked).
   **OSM built 10 Nov 2026**: Speed cameras and CCTV layers, read for the
   box on screen. Public Overpass refuses a cloud host, so red5 keeps them
   from a weekly Geofabrik Australia file (`map_osm.py refresh`). Victoria
   publishes fixed camera sites, a monthly list of approved mobile camera
   sites, and a monthly list of phone and seatbelt camera sites
   (data.vic.gov.au, CC BY): still to do, as an add-on, since some lists
   give addresses that need geocoding.
4. Where things are (devices, rooms, speakers).
5. Location history and its Settings.
6. Navigation by voice.

## Decided (David, 6 Nov 2026)

- **Menu:** Map is its own top-level entry, beside Chats and Media.
- **Tiles:** hosted to start (OpenFreeMap). A self-hosted Victoria
  PMTiles file on red5 is added later as the fallback.
- **History kept:** Settings offers 30 days, 90 days, one year and
  forever. The default is 90 days ("have options for all of them in
  settings but default to 90 days").
- **Navigation:** walking and driving together from the start. One
  routing engine serves both, with a mode switch; camera alerts are
  spoken in driving mode only.
